# AccountsManager

Неофициальное локальное приложение для нескольких аккаунтов Clash of Clans.
Linux MVP: общая панель КВ/ЛВК/Ranked, привязки кланов, планы переходов,
псевдонимы, порядок аккаунтов, SQLite и просмотр последнего снимка без интернета.

**Точный остаток Ranked пока не подтверждён и не показывается.**
Подробности и ограничения КВ/ЛВК: [контракт API](docs/api_contract.md).

## Сборка

Нужны Clang с поддержкой `-std=c++26`, CMake 4.4.5+, Qt 6.8+ (Core, Network,
Sql, Quick, QuickControls2), плагин QSQLITE, QML-модули Qt Quick Controls,
Material, Layouts и vcpkg.
В этой среде проверяется Qt 6.12. Зависимости vcpkg: nlohmann-json и
ayush272002-dotenv. CPR больше не используется. Установка системных пакетов
не выполняется сборочным скриптом.

```sh
make debug
make release
make run debug
make run release
```

Путь vcpkg по умолчанию — `$HOME/vcpkg`; можно передать `VCPKG_ROOT=/путь`.
Сборки разделены на `build/clang-debug` и `build/clang-release`.
Qt собирается и связывается штатными CMake-командами; QML включён в бинарный файл
через [qt_add_qml_module](https://doc.qt.io/qt-6/qt-add-qml-module.html).

## API-ключ

Создайте собственный ключ в [официальном Developer Portal](https://developer.clashofclans.com/)
и укажите разрешённый IP согласно настройкам портала. Приложение читает `API_KEY`
из окружения. Если переменная пуста, один раз читается `.env` из рабочего каталога:

```dotenv
API_KEY=ваш_собственный_ключ
```

`.env` уже исключён из Git. Не публикуйте ключ и не добавляйте его в команды с
литеральным значением, если они сохраняются в истории. Для запуска из рабочего
стола нужно передать окружение при запуске либо использовать корректный рабочий
каталог. Ключ не сохраняется в SQLite, QML или бинарном файле. Без ключа доступны
локальные настройки и кеш, а интерфейс показывает причину отсутствия обновлений.
HTTP 403 требует проверки ключа/доступа; это не состояние «атак нет».

## Использование

1. На вкладке «Аккаунты» добавьте публичный тег вида `#TAG`. Пароли и Supercell ID
   не нужны. Профиль проверяется асинхронно; недоступный аккаунт остаётся в списке
   с ошибкой, остальные продолжают работать.
2. При необходимости задайте псевдоним и закрепите клан обычной КВ. Пустая
   привязка означает текущий клан из профиля.
3. Отдельно задайте клан ЛВК. Смена текущего клана эту привязку не меняет.
4. План перехода содержит целевой тег и необязательное местное время
   `ГГГГ-ММ-ДДTчч:мм`. Для отмены очистите целевой клан. Переход выполняется
   только в игре; приложение его не автоматизирует и само не завершает план.
5. На панели видны независимые статусы режимов, источник, актуальность и ошибки.
   Сохранённые сведения имеют явную пометку; неизвестные значения не равны нулю.

Автообновление — каждые пять минут. В настройках: 0 — вручную, 1–1440 — период
в минутах. Кнопка обновления не обходит паузу после 429. Список можно переупорядочить.

## Цвета Omarchy

Приложение читает палитру активной темы из
`~/.local/state/omarchy/current/theme/colors.toml`. Фон, текст, акцент, выделение,
предупреждения и ошибки используют её цвета, включая светлый режим. Поддерживаются
цвета `#RRGGBB` с кавычками или без них, комментарии после значения и основные
альтернативные имена (`bg`, `fg`, `color0`, `color7` и другие).

Режим определяется по `mode` / `theme_type`, затем по файлу `light.mode`,
а при их отсутствии — по яркости фона. Тема применяется при запуске и обновляется
во время работы через файловые события, в том числе при замене каталога темы
или символической ссылки. Постоянного опроса и изменений конфигурации Omarchy нет.
Неполная/нечитаемая палитра сохраняет последнее корректное состояние; без Omarchy
используется резервная тёмная палитра. Большие или неподдерживаемые файлы не
исполняются и не интерпретируются как произвольный TOML.

Адаптирован только код чтения цветов и слежения за файлами; сведения об исходном
шаблоне и его лицензии — в [third-party notices](docs/third_party_notices.md).

## Локальные данные и разработка

База `accounts.sqlite` располагается в `QStandardPaths::AppDataLocation`.
На обычном Linux это обычно
`~/.local/share/AccountsManager/AccountsManager/accounts.sqlite`; точный путь
показан в настройках. Одновременный запуск двух экземпляров с одной базой запрещён
блокировкой. Старые API-ресурсы, не нужные текущему списку, удаляются из кеша.
Повреждённая или более новая база не пересоздаётся автоматически.

SQLite работает в отдельном потоке с одним соединением. Миграция версии и
изменения аккаунтов выполняются транзакционно через
[Qt SQL](https://doc.qt.io/qt-6/qsqldatabase.html#details), без ORM.
Демонстрационная выгрузка `player_profile.txt` больше не является точкой входа;
существующий файл не изменяется. Типы профиля и парсер сохранены.

Тестовая инфраструктура по решению автора в репозиторий не включена. Перед
завершением изменений нужны Debug/Release-сборки, внешние проверки предметной
логики и SQLite, `accounts-manager_qmllint`, ревью C++/QML и `graphify update .`.
Windows, уведомления, мобильные платформы и синхронизация отложены.

Приложение не одобрено Supercell. Перед публичным распространением необходимо
проверить актуальные условия Supercell и лицензии Qt и остальных зависимостей.
